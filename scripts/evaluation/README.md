# Evaluation scripts

Run these commands from the repository root after [setup](../../README.md#run-evaluations).

## Live benchmarks

`run_benchmark.py` coordinates the four case studies, starts a local engine, and records the selected models, commands, results, and logs in a run manifest. Run all four case studies with:

```bash
uv run python scripts/evaluation/run_benchmark.py --targets paper --user-model opus
```

Select `--targets malade`, `infoflow`, `tau2`, or `agentdojo` to run one case study. The [case study guides](../../README.md#experiments) give small validation commands. The default `paper` selection runs all four; translation has its [own harness](../../experiments/translation/).

Useful controls:

| Option | Purpose |
|---|---|
| `--output-root PATH` | Create the timestamped run in another directory |
| `--server-bin PATH` | Use an explicitly built engine |
| `--server-port PORT` | Choose the managed engine's port |
| `--no-start-server` | Use an existing engine configured through `SASY_URL` and client credentials |
| `--resume RUN_DIR` | Skip finished cells and resume incomplete work; repeat the original selection flags |
| `--retry-infrastructure-errors` | With `--resume`, retry infrastructure failures without replacing evaluated tau2 outcomes |
| `--cell-timeout SECONDS` | Bound a stalled experiment cell |

The engine is shared across cells, with session-bound policies. Resume continues from saved results; in-flight requests restart.

## Recompute tables

Generate a case study's tables from its saved manifest:

```bash
uv run python scripts/evaluation/summarize_{case_study}.py results/{case_study}/manifest.json
```

Replace `{case_study}` with `malade`, `tau2`, `infoflow`, or `agentdojo`. The summarizers print Markdown; `--md PATH` saves tables. Runtime and cost are means over the underlying trials or scenarios. See the [AgentDojo guide](../../experiments/agentdojo/) for ASR definitions and the effect audit.

## Latency

`run_latency_sweep.py` collects live client-side and server-side timings over a fixed airline task set at multiple concurrency levels. `summarize_latency_sessions.py` computes statistics and whole-session bootstrap intervals.

```bash
uv run python scripts/evaluation/run_latency_sweep.py
uv run python scripts/evaluation/summarize_latency_sessions.py results/latency-sweep/<run>
```

Saved results are under `results/latency/live/` and `results/latency/replay/`, including `live/bootstrap_summary.json`. The sweep reducers accept newly generated run directories. See the saved [results guide](../../results/latency/README.md).

`run_latency_microbench.py` can replay saved authorization requests against a compatible persisted graph. Replay measures authorization against a saved graph, excluding model latency, tool execution, client instrumentation, and graph updates. It requires matching graph and capture artifacts, which are generated by live runs and omitted from the saved results.

```bash
uv run python scripts/evaluation/run_latency_microbench.py --help
```

## Artifacts

Saved results live under `results/<case-study>/`; new benchmark runs use `results/<timestamp>/`. Keep a manifest together with its run files. Readers resolve relative artifact paths against the containing manifest.
